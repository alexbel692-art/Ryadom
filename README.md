# Рядом — своя программа удалённого доступа

Аналог AnyDesk, RuDesktop и «Мой ассистент» для поддержки своих компьютеров. Весь трафик идёт через ваш сервер.

```
 Компьютер сотрудника ──┐                       ┌── Ваш Mac / ПК специалиста
   (клиент «Рядом»)     │   ┌───────────────┐   │    (клиент «Рядом»)
                        └──►│  VPS «Рядом»  │◄──┘
                            │ hbbs  — ID    │   прямое P2P-соединение, если получится,
                            │ hbbr  — relay │   иначе через hbbr
                            │ панель + API  │◄── браузер администратора
                            └───────────────┘
```

| Часть | Что это | Где |
|---|---|---|
| **Клиент** | Программа для Windows, macOS, Linux, Android. Через неё подключаются и принимают подключения | `client/`, собирается в GitHub Actions этого репозитория |
| **hbbs / hbbr** | Сервер ID и ретрансляции (официальный open-source RustDesk Server) | `server/docker-compose.yml` |
| **Панель** | Своя веб-панель на Python (написана с нуля, без зависимостей) | `panel/` |

### Что умеет панель

- **Устройства**: все компьютеры с клиентом появляются сами. Видно, кто в сети, ОС, пользователь, версия, IP.
  Можно задать название, заметку и владельца.
- **«Подключиться» и «Файлы»** в один клик: открывается программа и сразу начинает подключение.
- **«Разорвать»**: принудительно завершить чужой сеанс на устройстве (срабатывает за ~15 с).
- **Журнал сеансов**: кто, когда, к какому компьютеру, с какого IP, тип подключения, сколько длилось.
- **Журнал файлов**: что и куда передавали.
- **Пользователи**: учётки специалистов. Специалист входит в клиенте и видит список устройств
  и свою адресную книгу на любом компьютере. Администратор видит всё и входит в панель.
- **Страница загрузки для сотрудников** (`https://домен/`): кнопка скачивания под их систему и инструкция в 3 шага.
- Защита: пароли в PBKDF2, блокировка после 10 неудачных входов, HTTPS через Caddy, только ключевые подключения к hbbs.

## Установка сервера (≈10 минут)

Нужен VPS с Ubuntu 22.04/24.04 или Debian 12, 1 vCPU, 1 ГБ ОЗУ и домен (например `remote.firma.ru`),
A-запись которого указывает на IP VPS. Без домена тоже можно, но тогда панель будет без HTTPS.

```bash
ssh root@IP_СЕРВЕРА
git clone https://github.com/alexbel692-art/Ryadom /opt/ryadom
# с Mac положите выданный ключ:  scp id_ed25519 root@IP_СЕРВЕРА:/opt/ryadom/server/
cd /opt/ryadom/server
bash install.sh remote.firma.ru
```

Если вам выдали файл ключа `id_ed25519`, сначала положите его в `/opt/ryadom/server/`:
тогда ключ совпадёт с уже собранными клиентами.

Скрипт поставит Docker, откроет порты в ufw, запустит всё и напечатает:
- адрес панели (`https://remote.firma.ru/admin`), логин `admin` и сгенерированный пароль;
- ключ сервера.

**Порты** (если у хостинга есть свой файрвол, откройте их там):
TCP `21115–21117`, UDP `21116`, TCP `80` и `443`. Без домена вместо 80/443 нужен TCP `21114`.

## Клиент

Инструкция: **[client/BUILD.md](client/BUILD.md)**. Коротко: впишите домен в `client/server.json`,
затем на GitHub откройте Actions → нужная платформа → Run workflow. Готовые файлы заберите из Artifacts и положите в `server/downloads/`.

Пока своей сборки нет, работает стандартный RustDesk: в нём Настройки → Сеть → вставить строку конфигурации
из панели (раздел «Подключение»).

## Как пользоваться

1. Отправьте сотруднику ссылку `https://remote.firma.ru/`. Он скачает и запустит программу.
2. Компьютер сам появится в панели. Нажмите **Подключиться**, у сотрудника появится запрос, он нажимает **Принять**.
3. Для серверов и компьютеров без людей: на этом компьютере в клиенте задайте **постоянный пароль**
   (Настройки → Безопасность) и установите программу как службу. Тогда подключение работает без подтверждения.
4. Специалистам заведите учётки в разделе «Пользователи». В клиенте кнопка **Войти**: появятся вкладки
   «Доступные устройства» и «Адресная книга».

## Обслуживание

```bash
cd /opt/ryadom/server
docker compose logs -f panel                        # логи панели
docker compose --profile https pull                 # обновить hbbs/hbbr/caddy
docker compose --profile https up -d --build        # применить (без домена — без --profile https)
```

**Резервная копия.** Самое важное — `server/data/` (ключ сервера: без него все клиенты
придётся пересобирать) и `server/panel-data/` (база панели). Копируйте их, например, раз в день:
```bash
tar czf /root/ryadom-backup-$(date +%F).tgz -C /opt/ryadom/server data panel-data .env
```

**Забыли пароль администратора:**
```bash
docker compose exec panel python3 -c "import app; app.db(); app.ex('UPDATE users SET pw_hash=? WHERE name=?', (app.hash_password('НовыйПароль123'), 'admin'))"
```

## Настройки (`server/.env`)

| Переменная | Значение |
|---|---|
| `DOMAIN` | домен или IP сервера |
| `API_URL` | `https://домен` или `http://IP:21114` |
| `APP_NAME` | название в панели и на странице загрузки |
| `URI_SCHEME` | `ryadom` для своей сборки, `rustdesk` для стандартного клиента |
| `AUDIT_KEEP_DAYS` | сколько дней хранить журнал (365) |

После изменения: `docker compose --profile https up -d`.

## Лицензии

- Клиент и hbbs/hbbr — RustDesk, лицензия **AGPL-3.0**. Для своих сотрудников можно использовать без ограничений.
  Если будете раздавать изменённый клиент посторонним (клиентам, на продажу), исходники изменений нужно
  опубликовать (этот публичный репозиторий это и делает). Workflow сборки взяты из rdgen (GPL-3.0, `.github/LICENSE-rdgen`).
- Панель (`panel/`) — ваш код, ограничений нет.

## Известные ограничения

- Кнопка «Подключиться» открывает программу по ссылке `ryadom://`. На Windows схема регистрируется при установке.
  На macOS в некоторых версиях сборки ссылка может не открыться. Тогда нажмите на ID в панели (он скопируется)
  и вставьте его в программу.
- Подключения из браузера без установки программы в этой версии нет: со стороны специалиста нужен клиент.
- Группы устройств и права «кто к какому компьютеру может подключаться» не реализованы. Специалист видит
  устройства, на которых он входил в клиенте или которые ему назначены в панели, администратор видит все.
